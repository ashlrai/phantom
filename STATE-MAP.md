# Fleet machinery state map

Evidence: RQ-STATEMAP-HYGIENE-1, 2026-11-16; repository behavior, not proof of deployed behavior. `R` means `~/.ashlr-runs`, `Q` means `R/queue`, and `A` means the configured `ashlrHome()` (normally `~/.ashlr`). Times below are source defaults; host overrides can differ. No live machinery or state was changed.

## Coverage and custody

The original [manifest](fleet/manifest.json) contained 13 managed, 8 manual and 12 pinned entries. This change adds eight managed dependencies: seven already in [install.sh](contrib/mac/install.sh), plus `queue_gate.py`, imported by both dispatcher and restocker. The resulting inventory has 21 managed, 8 manual and 12 pinned entries. JSON configuration retains mode 0644.

Host enumeration of `R/bin` and `Q` returned `PermissionError`; installed hashes, queue values, breaker files and dynamic callers remain unknown. Names-only inspection found `A/node-pool/config.json` and `primary-mirror.json`; `A/nodes` was empty. No config, mirror, job body, credential or queue payload was read.

Plist presence does not establish that launchd loaded it. Only executable/script names and scheduling metadata were inspected; inline shell commands were not logged.

## Dispatcher state and transitions

The [dispatcher](contrib/mac/dispatchd.py) owns a tick under `Q/dispatchd.tick.lock`. Its `SlotWriter` additionally holds the controller lock; `Q/ready.lock` protects queue snapshots/rewrites and route receipts, not slow preparation. External host writers are not proven to share these locks. [Controller](contrib/mac/fleet_controller.py), [concurrency](contrib/mac/concurrency.py), [restocker](contrib/mac/restock.py) and [precheck](contrib/mac/launch_precheck.py) links below name the implementations.

## Janitor and deployment machines

The active RQ-JANITOR-1 claim owns operational cleanup. This task only maps it. [Disk plan](src/core/disk-maint/plan.ts) selects candidates; [apply](src/core/disk-maint/apply.ts) revalidates them through the same [protect list](src/core/disk-maint/protect.ts). Classes transition excluded/too-young/protected/unknown → candidate → done/refused/failed. Compression, rotation and deletion are separate actions; revalidation can refuse a once-valid plan.

| Janitor class | Eligibility / transition / failure |
|---|---|
| run-logs, agent-sessions, ashlr-logs | Quiet logs age into compression/deletion; active/unknown jobs use conservative retention. Rotating active logs changes filenames before compression. |
| recovery-dirs, staging, caches | Rebuildable leftovers only, with age/type/root checks; symlinks and protected roots refuse. |
| worktrees-runs, worktrees-jobs | Runs require merged/empty; job trees require merged. Ledger, keep pins, age and non-force git removal all constrain deletion; unreadable ledger never proves terminal state. |
| bridge-targets | Quiet build output may be removed; bridge [disk lifecycle](scripts/bridge/disk.py) separately uses shared/exclusive target leases and cleanup-pending receipts to defer busy targets. |
| job-artifacts | Completed, inactive job and safe sidecar checks at plan and apply; activity/completion uncertainty refuses. |
| venvs, hub-claude | Explicit `--allow` class opt-in; protected auth/models/git/Docker/client/Documents roots still refuse. |

The managed [wt-prune](contrib/mac/wt-prune.py) pair and manual [branch gardener](contrib/mac/branch-gardener.py) have separate dry-run/apply paths and git evidence checks; staged/quarantined/kept or unknown work is not disposable. Runtime bin, metrics, pins and credentials are not janitor candidates.

[Fleet sync](fleet/sync.py) transitions new/changed/unchanged → installed or error for managed entries only; backs up before replace and verifies the installed digest. Manual/pinned/absent/drift/pin-mismatch remain observations. Backup restoration is a separate explicit operation; unmanaged sweep reports names without deleting them. This PR changes candidate inventory only and does not authorize live installation or bypass Security pins.
