# GPT-6.1 Terra qualification

This offline scorer compares matched, independently collected results; it makes no provider calls and grants no quota, budget or production routing. Do not run live trials unless existing account access and remaining budgets allow them. Use private fixtures and receipts; never put credentials, prompts with private data, screenshots or raw model responses in this repository.

For every case exported by `terra-eval.mjs`, run both `gpt-6.1-sol` and `gpt-6.1-terra` with `medium` effort, the same prompt, tools, context, harness and trial count. For `triage`, additionally run Terra at `none` (Sol has no `none`). Use the Responses API for API tool calls; for the cheaper Codex tier, repeat the coding cases with both models in the same Codex harness and report separately. Do not combine API and Codex receipts. For visual and computer-verifier cases, capture the entire `terra-verifier.html` at a 1280 × 900 viewport and pass the identical screenshot to both models. These cases assess Terra as a candidate default visual and computer-use verifier. They test screen-based verification, not a live computer-use action loop. Keep the expected answers private from the model. Randomize order, reset state, record errors, and use repeated paired trials.

Each receipt is JSON `{ "trials": 1, "results": [...] }`. Each result has `arm` (`sol`, `terra`, or `terra-none`), exact `model`, `effort`, `caseId`, one-based `trial`, `answer`, `elapsedMs`, `inputTokens`, and `outputTokens`. Include all cases for the first two arms and triage only for `terra-none`. On failures record an empty answer, with measured usage and latency; if usage is unavailable, do not fabricate a receipt. Run `node benchmarks/terra-eval.mjs /private/receipt.json`. The output gives per-lane pass counts, token totals and latency totals, not a model ranking or a production promotion. Token prices exclude cached pricing, tool charges and long-context adjustments; compare actual billing separately. The tiny fixed suite is a smoke test, not evidence of quality parity: use representative held-out coding, visual and interactive computer-use tasks before changing defaults.

API facts: [Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol). The 1,050,000-token API window does not establish a Codex seat's native context or availability; its own model catalog remains authoritative.
