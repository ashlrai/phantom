# Prompt-variant A/B evaluation and promotion

`phm eval prompts --dataset jobs.jsonl [--spec experiment.json] [--promote] [--write registry.json] [--check registry.json] [--json]` replays prompt variants per job class over a frozen router-eval.v1 outcome log and prints the before/after A/B table: control vs challenger merge rate, cost per merged PR and wall time, each with intervals. It reads local files only and makes no network requests. `--spec` defaults to the builtin experiment (docs/tests/secrets classes, `prompt:plain` control, `prompt:adaptive` challenger); a spec file declares its own class matchers (case-insensitive task regex, plus exact repo/tier/priority fields), control arm and challenger arms, and optional gate overrides.

The promotion gate fires per class: both arms need a minimum resolved cohort, unobserved decisions stay under a coverage cap, the challenger's Wilson 95% interval must clear the control's entirely, and cost per merged PR may not regress past the configured tolerance. Anything short is a documented hold (`no-lift`, `not-significant`, `insufficient-data`, `thin-coverage`, `cost-regression`) — never a quiet promotion. `--promote` merges the verdicts into `~/.ashlr/eval/prompts/promotions.json`; uncovered classes keep their stored records. `phm pulse` renders that registry as the "Prompt variants" section — each promoted class's before→after merge rate, cohort sizes and lift — and `assignPromptVariant` in `src/core/eval/prompt-variants.ts` reads it at dispatch time: a promoted class routes to its winner, a class mid-experiment gets a deterministic A/B bucket by job id, unmatched jobs keep incumbent behavior.

`--check` compares a replay's promoted/held verdicts and before/after numbers against a committed promotions file and exits 1 on drift — the regression gate `test/prompt-ab.test.ts` runs against `benchmarks/prompt-ab/`, which holds the frozen day, the experiment spec, the committed promotions and the regeneration commands.
