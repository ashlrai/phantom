# Fleet runs v1

`GET /api/verse/fleet/runs` returns a `FleetRunsV1` snapshot described by the
[JSON Schema](../../schema/fleet-runs.v1.schema.json). The desktop polls every
5 seconds. The server caches snapshots for two seconds. Each source can fail
independently; empty arrays can reflect unavailable data, so check `sources`.

For a locally started `phm verse`, set `PHM_URL` and `PHM_READ_TOKEN` privately
from its startup JSON (the desktop manages its own credentials):

```sh
curl -fsS -H "X-Ashlr-Token: $PHM_READ_TOKEN" "$PHM_URL/api/verse/fleet/runs"
```

| Fields | Meaning and source |
| --- | --- |
| `v`, `generatedAt` | Contract version and snapshot time, generated by the server. |
| `sources` | State of `runsDir`, `workers`, `inbox`, `codex`, and `merges`, respectively. |
| `lastTick`, `paused`, `memFreePct`, `diskFreeGb` | Last dispatch tick, pause state, free memory percent and free disk GB from `status.json` in the runs directory under the home folder. |
| `switches`, `claudeLane` | Present dispatch switch names and selected Claude lane from switch files and `claude-lane.state` in the runs directory. |
| `lanes` | Lane name, running, target and queued counts, held state and reason, tokens in the last hour, merges and merge rate over 24 hours; derived from `status.json` and `jobs.jsonl` in the runs directory. |
| `workers` | Live job, repo, lane, tier and age in seconds from the local process list. |
| `leaders`, `orchestratorAgents` | Leader labels and ages, and orchestrator agent count, from the local process list. |
| `publishesLastHour` | Job, lane, URL and time of recent publishes from `jobs.jsonl`. |
| `mergesLastHour` | Count and items (repo, PR number and title) from GitHub's merged PR search. |
| `events` | Time, kind and text from `dispatch-events.log`. |
| `codexPersonal` | Personal Codex session usage percent, reset time and observation time from local Codex session usage data. |
| `inbox` | Recent entry time, source and text from `MASON-INBOX.md`. |
| `drop` | Pending lane and file basenames and done count from the leader drop directory. |

Source states are `healthy` (reader succeeded), `degraded` (reader failed or
reported degraded), `missing` (reader reported missing or no personal Codex
session was found), and `not-landed` (reader module is unavailable). A healthy
source is not a guarantee that every underlying value is known.

## Inbox submission

With dispatch enabled, use the separate mutation token in the same header:

```sh
curl -fsS -X POST -H "X-Ashlr-Token: $PHM_MUTATION_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text":"Please review the demo","source":"Mason"}' \
  "$PHM_URL/api/verse/fleet/runs/inbox"
```

The body requires nonblank `text` (at most 6000 characters after trimming) and
allows `source` (1–40 letters, digits, spaces, dots, underscores or hyphens).
No other keys are accepted. Success is `201 {"ok":true,"at":"..."}` on the
first post and `200` with `duplicate:true` on a repost inside the dedupe
window; receipts persist under the runs dir (`ASHLR_RUNS_DIR`, else
`~/.ashlr-runs`), so the dedupe survives a Hub restart. Invalid bodies return
`400` with `VERSE_INVALID`; a refused entry returns `422` with
`INBOX_REFUSED` and a reason; an unavailable inbox returns `503` with
`INBOX_UNAVAILABLE`; an unreadable receipt store returns `503` with
`INBOX_RECEIPTS_UNREADABLE` without writing the entry. Dispatch disabled
returns `404`. The mutation gate also applies.

## For agents

Read `sources` before trusting a field; treat null as unknown, never zero. The
inbox is Mason's channel to the leaders, so agents must not post to it as if
they were Mason. A snapshot is an observation, not authority to act.
