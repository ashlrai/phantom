# Fleet graph v1

`GET /api/verse/fleet/graph` returns the `graph.v1` fleet registry — the
fleet's declared agents, engine/account identities, model catalogs and MCP
server identities, plus the `routes-to` and agent-relationship edges between
them. `GET /api/verse/fleet/graph?live=1` additionally joins the
`graph-live.v1` projection: per-node capacity, metered cost, quota standing
and reset times from the same evidence the dispatch gates read.

For a locally started `phm verse`, set `PHM_URL` and `PHM_READ_TOKEN`
privately from its startup JSON (the desktop manages its own credentials):

```sh
curl -fsS -H "X-Ashlr-Token: $PHM_READ_TOKEN" "$PHM_URL/api/verse/fleet/graph?live=1"
```

| Query | Effect |
| --- | --- |
| `live=1` | Adds the `live` field (below). `live` is the only accepted key and `1` its only accepted value. |

Any other query key or value returns `400` with `VERSE_INVALID`. The route is
read-only: other methods return `405`.

| Fields | Meaning and source |
| --- | --- |
| `v`, `generatedAt` | Contract version and snapshot time, generated by the server. |
| `graph` | The `RegistryGraph` projection (`graph.v1`: `nodes`, `edges`, `issues`, `complete`, `sources`). See [types.ts](../../src/core/graph/types.ts). |
| `live` | Present only for `?live=1`: the `GraphLiveProjection` (`graph-live.v1`). Every registry node is repeated with a `live` field — `state`, `usedPercent`, `quota`, `resetsAtMs`, `spentTodayUsd`, `readingAgeMs`, `stale`, `reasons` — plus `counts.byState`, `budget` and `issues`. See [graph-live.ts](../../src/core/fleet/graph-live.ts). |
| `sources` | Per-source read state for `fleet` and `seats`, the same states `graph.sources` reports. |

Source states are `loaded` (the input parsed), `missing` (the file is absent
or no seat inventory is configured), `invalid` (the input parsed as JSON but
failed the allowlist contract) and `unavailable` (the file or the discovery
path could not be read). A missing or invalid source is a state, not an
error: the response is still `200`, carrying whatever projected, with
`complete: false` and the corresponding `issues` entries.

## Inputs

The route reads the same evidence the graph pipeline already reads:

- `fleet` — `$ASHLR_HOME/fleet/fleet.json`, the shared fleet document. The
  `fleet.v1` registry seed sections (`agents`, `mcp`, `edges`) live in it.
- `seats` — the public `seats` half of `discoverSeats(cfg)`, the same
  inventory the desktop console lists.

Both inputs are allowlist-parsed: only ids, engines, account ids and model
ids project. Launcher commands, environment maps, labels, notes and
credential fields are never copied into the response — a seat row carrying
`apiKey`, `env`, `command` or `launches` contributes only its public fields.

## Live node states

`live.nodes[].live.state` is an observation, never a dispatch decision —
`untracked` (no live signal applies), `ready` (fresh headroom), `limited`
(warn-level), `unknown` (a reading was expected but none qualified), `stale`
(every dated reading exceeded the staleness bound), `held` (a gate or policy
refused) or `exhausted` (provably saturated). The runtime gates
(`subscriptionAllows`, quota reservation, the router) remain authoritative.

## For agents

Read `sources` and `issues` before trusting the graph; `complete` means a
structurally complete projection of the selected inputs, not live readiness.
Treat `null` live fields as unknown, never zero. A `routes-to` edge records a
binding or catalog listing, not permission to execute.
