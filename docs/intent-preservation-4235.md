Original exported interfaces were `IntentSummary`, `IntentAddInput`, `IntentUpdateInput`, `MergedPullNote`, `ShippedReleaseNote`, and `SweepRow`; their original module path is absent. Similar types exist in current summary, evidence and sweep modules, but full type compatibility is unproven.

Original `src/cli/intent.ts` exported `cmdIntent`: `list [--status]`, `get <id>`, `add` with title/source, owner, repeated RQ, status, stale timer, verbatim and date, `update` with fields and verification evidence, multi-file `import`, `stale [--apply]`, `link` with repo/number/title/branch/url, and `ship` with release/notes/repeated RQ. It provided help and JSON output, rejected unknown options and invalid statuses, and returned 2 for errors. Master instead exposes `phm fleet intent-read`, `intent-import`, `intent-evidence`, `intent-summary`, and `intent-sweep` via their respective `src/cli/fleet-intent-*.ts` exports. These are changed command names and contracts, with preview/apply evidence semantics; add and update have no equivalent. `test/intent-guide-reconcile-09spl1.test.ts` “imports fake copies, previews and records linked evidence, then rereads” covers the current flow, not CLI compatibility.

The original tree search finds `src/core/world/read.ts` calling `intentSummary` and passing counts and stale items to `src/core/world/project.ts`, which projects intent observations and stale blind spots. Original test: “puts ledger totals on the world model and stale items in blind spots”. At inspected master, `src/core/world/read.ts` and `project.ts` contain no intent integration: **missing**, despite the independent summary module. The original `src/core/verse/fleet-runs-api.ts` extracts valid rows from `mergesLastHour.items`, calls `noteMergedPulls` with the runs root and clock, and catches failures so the snapshot survives. That caller is absent on inspected master: **missing** automatic merge-snapshot integration; no original test in the named test file covers that caller. Original `src/core/mcp-native.ts` also exposes intent read and mutation tools; master has the separate read-only `src/mcp/fleet-intent-read.ts`, so mutation surface equivalence is **missing**, not inferred from the CLI.

This is bounded source evidence, not proof of complete preservation, deployed behavior, or authority to close #4235.
