# Phantom 3.30.34 release notes

Hand-written summary of what shipped since 3.30.33 (2026-11-13). The generated
`CHANGELOG.md` entry for this release lists each change under its job id;
this page is the readable version, grouped by theme.

## Fleet viz

- A unified fleet compute and agent view in the Fleet page, with a 2D fleet map and a 3D compute scene in the Verse company view.
- A live sessions map shows which agent sessions are running on which machine.
- Company overview in the Verse company pane summarizes the org at a glance.
- Fleet page layout polish: live board, machine cards and lanes read more clearly.
- The desktop app can open the Fleet world directly (new menu entry and command key).
- Empty-state panels explain themselves when no jobs are running.
- The Channels pane gains an Orchestration card and a Teammate tasks card.

## Orchestration

- `phm fleet orchestrate` plans and runs a goal across the fleet; the chief-of-staff command shares the same path.
- Orchestration journal entries are readable from the desktop.
- Pack-aware node capacity: nodes report their real capacity and can self-update to the current Phantom version.
- Machine telemetry for each node is documented in `docs/MACHINE-TELEMETRY.md`.
- Route hysteresis stops work from flapping between lanes on small score changes (`docs/ROUTE-HYSTERESIS.md`).
- Merge retries detect arm conflicts and retry sooner, cutting merge latency.
- Cross-review runs report more detail on what was reviewed.
- The cos worker has end-to-end verification coverage.

## Agent network

- Agent network work dispatch: peers can hand work to each other over the peer bus.
- A bus work feed (v2) records and reads dispatched work; `phm fleet work-feed` reads it from the CLI.
- Claims can be bound to a thread with `phm fleet claim-bind`, from the CLI or the desktop Claim notices card.
- Claim notices show delivery state and Slack delivery results.
- Peer sessions renew and peer HTTP calls retry instead of failing on a transient error.
- Bridge claims are qualified for expiry, return, concurrency and isolation across the CLI, HTTP and MCP surfaces.

## Owner assist

- iMessage teammate tasks: unsent tasks can be cancelled, CLI actions print receipts, and queue binding is recorded.
- Slack replies keep the identity and channel of the thread they answer, and Slack trace output shows the channel.
- Slack ingress, status and journal paths have stronger uniqueness and freshness checks.
- Owner-facing evidence for Slack and desktop transport is preserved across restarts.

## Infrastructure

- `contrib/mac/publish.sh` scopes the pull request diff to the worktree.
- Scheduled loop support for recurring fleet work.
- Worker scratch files (`notes.md`, `task_plan.md`) are removed from the repo root.
- CI fixes: an intentional ESC in an ANSI regex no longer fails Lint, and several flaky-gate fixups landed.
- README links the agent toolchain guide by URL.
